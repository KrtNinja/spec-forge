# Проверка JavaScript-кода

Проверки предназначены для разработчиков Spec Forge. Они не добавляют инструкции
в контекст модели, которая составляет требования.

## Локальный запуск

Нужны Git и Node.js. Минимальная версия для тестов — 22.5.1; для полного набора
инструментов используйте актуальную Node.js 22.

```sh
npm ci --ignore-scripts
npm test
npm run check
npm run coverage
```

Проверяются добавленные в Git файлы `.js`, `.mjs` и `.cjs` во всём репозитории.
Перед локальной проверкой новых файлов выполните `git add`.
Тесты называются `*.test.js`, `*.test.mjs`, `*.test.cjs` (также поддерживается `.spec`).
Каталог `tests/` предназначен для тестов и их вспомогательных файлов.

## В каждом PR

- Тесты на Node.js 22.5.1 и актуальной версии 22. Ошибка теста завершает проверку неуспешно.
- ESLint: ошибки кода, неиспользуемые переменные, вложенность и сложность функций.
  Сложность функции должна быть меньше 10, вложенность — не больше 4.
- TypeScript проверяет типы JavaScript без сборки: `allowJs`, `checkJs`, `strict`, `noEmit`.
- Поиск повторов: не больше 2% в коде и 10% в тестах.
- Покрытие: текстовый отчёт, HTML и LCOV, включая неисполненные файлы.
  Процент покрытия пока информационный, без произвольного обязательного порога.

Отчёты доступны в GitHub Actions как `quality-reports`. Эти проверки выполняются
также после вливания в `main`. Новый коммит отменяет устаревший прогон того же PR.
Зависимости закреплены в `package-lock.json`, установка в Actions выполняется через `npm ci`.

Пока рабочего кода продукта нет, вывод явно сообщает об этом. Тесты инфраструктуры
не считаются тестами продукта: появление рабочего кода без тестов продукта вызывает ошибку.
Само наличие теста не доказывает полноту проверок — ожидаемый результат сверяют с требованиями.

## Мутационные тесты — только вручную

После вливания workflow в `main`: **Actions → mutation → Run workflow**, затем
выберите нужную ветку. Автоматического запуска на PR, push или по расписанию нет.
Агент не запускает эту проверку без явного запроса пользователя.

Используется тот же `unclebob/mutator`, что в sdd-planner, с закреплёнными коммитами
mutator и crapper. Проверяется весь рабочий JavaScript-код, включая места без покрытия.
`tools/`, тесты и `*.config.mjs` в мутационный прогон продукта не входят.
Выжившая мутация или ошибка исходных тестов делает запуск неуспешным.
Отчёты сохраняются как `mutation-reports`. Ограничение времени — 120 минут.
Без рабочего кода запуск явно сообщает, что мутационная проверка не выполнялась.

## Границы проверки

Проверка сложности выполняется ESLint, повторов — jscpd. Отдельные crapper/CRAP,
dryer и проверка графа зависимостей из прежнего проекта сейчас не перенесены.
Старые эталоны, допуски накопленных ошибок и тесты sdd-planner не используются.

Зелёные Actions сами по себе не запрещают вливание красного PR: для этого владелец
включает обязательные проверки ветки в настройках GitHub.
