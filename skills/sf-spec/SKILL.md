# sf-spec — подготовка требований

Сначала вызови `spec_forge` с действием `status` и командой `sf-spec`; имя задачи после `/sf-spec` передай в `task`. Не видишь `spec_forge` — найди его поиском инструментов, пробуя разные запросы.

Задача выбрана — прочитай её `brainstorming.md`, `questions.md` и `spec.md`, если они есть, и действуй по ответу `status`.

## Требования

- Требования выводи только из «Решений» `brainstorming.md`. Рекомендация без решения пользователя и решение с «Заменено» основанием не служат.
- Одно правило — одна запись `FR-…` по образцу ниже: что видит и делает пользователь, одним-двумя предложениями; «Пример» с конкретным исходом — одной строкой; «Основание» — номера решений, из которых правило выведено.
- Граничное значение — парой в примере: что ещё проходит и что уже нет.
- Не пиши о коде: ни путей и файлов, ни классов и методов. В `brainstorming.md` и `_work/` ссылки на код уместны, в `spec.md` — нет.
- «Не входит в задачу» — из одноимённого раздела `brainstorming.md`.
- Для правила не хватает решения — не додумывай, запиши вопрос с «Этап: sf-spec». Блокирующий обсуди с пользователем сразу, неблокирующий оставь открытым и продолжай.

## Образец spec.md

```markdown
# Поиск заказа по номеру

Статус: черновик

## Цель

Покупатель находит свой заказ по номеру из письма, не листая историю заказов.

## Требования

### FR-01

Покупатель вводит полный номер заказа и видит карточку своего заказа.

- Пример: Анна вводит 10234 — открывается её заказ 10234 «Доставлен»
- Основание: D-01

### FR-02

Чужой и несуществующий заказ выглядят одинаково: сообщение «Заказ не найден».

- Пример: Борис вводит 10234 — «Заказ не найден»; Анна вводит 99999 — то же сообщение
- Основание: D-03, D-04

## Не входит в задачу

- Поиск в админке

## Вопросы

Открытые вопросы и ответы — в [questions.md](questions.md).
```

Раздел «Вопросы» — только если есть `questions.md`.

## Проверка и одобрение

- `check` без ошибок — вызови `status` и предложи его варианты: «Проверить требования» (рекомендую), а «Одобрить» — только если `check` выдал строку одобрения.
- Открытые вопросы мешают только одобрению: объясни это и предложи разобрать их. Ответ бизнеса или разработчика придёт через `sf-note`.
- «Одобрить» — только по явному решению пользователя: замени строку статуса строкой из ответа `check`, не меняя её, и снова вызови `check`.
