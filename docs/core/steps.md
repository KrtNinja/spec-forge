# План реализации Spec Forge

Временный документ: порядок реализации, отложенные решения и подсказки к блокам. Устройство системы описано в [design.md](design.md) и `design.md` этапов как готовое. Постоянные документы на этот файл не ссылаются; после блока 8 он удаляется.

## Как продолжить работу

Поручение агенту — «Продолжи работу по docs/core/steps.md». Каждый блок делается двумя PR — критерии и реализация, по разделу «Критерии и реализация» [AGENTS.md](../../AGENTS.md). Ветка критериев блока — `criteria/block-N`.

1. Текущий блок — тот, у которого открыт PR из `criteria/block-N` в main. Дальше работай по AGENTS.md этой ветки: состав работы — в описании PR критериев, что осталось — падающие тесты.
2. Открытого PR критериев нет — составь критерии следующего блока вместе с владельцем: начни с решений, записанных у блока, развилки обсуждай вопросами.

## Блоки

Блоки 1–7 завершены.

8. Инструмент прогона на настоящем GigaCode: владелец запускает его сам, когда меняет правила, скиллы или ответы инструмента.
   - Решено с владельцем:
     - Инструмент запускается на компьютере с GigaCode, где нет Claude и Codex. Отчёт владелец отправляет Claude или ChatGPT, и вердикт выносит тот. Проверок сверх `check` и `status` в инструменте нет.
     - Используется только GigaCode, без запасного пути на другой модели.
     - Журнал вызовов `spec_forge` пишет MCP-сервер: аргументы и ответ каждого вызова, только когда задан путь к файлу журнала в переменной окружения; иначе сервер ничего не пишет. Это новая пишущая обязанность: правка «Что можно писать» в `core/design.md`, затем критерии и реализация.
   - Подсказки к критериям:
     - Пользователя играет сценарий. Реплики пишутся по смыслу, без номеров вопросов. Следующая реплика отправляется по условию на журнал или файлы задачи, например «`status` показал переход» или «появился `spec.md`». Общая реплика «продолжай» повторяется, пока условие не выполнено, но не больше заданного числа раз.
     - Ход — `gigacode -p` для новой сессии или `gigacode --resume <id> -p`, с `--approval-mode auto-edit --output-format json -m <модель>` и бюджетом ходов и времени. `session_id` берётся из вывода; `/clear` — новая сессия без `--resume`.
     - Стенд — копия образца проекта во временной папке с `.gigacode/settings.json`: в нём вызовы `spec_forge` разрешены в `permissions.allow`, запись истории не выключена.
     - Отчёт — один Markdown-файл: ожидания сценария и как выносить вердикт; по каждому прогону — модель, реплики и ответы агента, вызовы `spec_forge` между ними, коды возврата (53 — исчерпаны ходы, 55 — бюджет), итоговые документы задачи. Сценарий гоняется заданное число раз на каждой модели.
     - Место — `tools/model-run/`: скрипт, сценарии, образец проекта, порядок запуска. Это инструмент разработки, а не поведение расширения, поэтому он делается одним PR после вливания журнала.
     - Узнать первым прогоном: срабатывают ли `/sf-…` внутри `-p`; доходит ли переменная окружения до MCP-сервера, а если нет — как включать журнал иначе; проходит ли запуск отдельного агента без подтверждения.
