# sf-note: устройство

Как выполнены [требования этапа](requirements.md). Опирается на [общее устройство](../core/design.md).

Документы, которые скилл читает после `status`: `brainstorming.md`, `questions.md`, `spec.md`.

## Новые сведения

- Агент по смыслу называет решения `D-…` и вопросы `Q-…`, которых касаются новые сведения. `check` возвращает FR, зависящие от них по ссылкам «Основание».
- Если новые сведения меняют или добавляют решение или отвечают на открытый вопрос, агент записывает новое решение `D-…` по общему формату `brainstorming.md`.

## Изменение одобренного документа

Если сумма не совпадает, `check` находит в истории git последний коммит `spec.md` с той же отметкой одобрения и показывает разницу. По ней агент оценивает смысл:
- Смысл не изменился (FR-24) — это обновление суммы, а не новое одобрение. Агент вставляет строку из `check`, а `check` переносит в неё прежнюю дату одобрения.
- Смысл изменился — агент ставит «Статус: черновик», и требуется повторное одобрение по FR-21.

Если одобренной версии в истории git нет, `check` прямо сообщает: «Одобренной версии в git нет, сравнить не с чем».
