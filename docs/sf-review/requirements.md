# sf-review: требования

Проверка требований ИИ в отдельном контексте и разбор замечаний с пользователем.

Зависит от: FR-07, FR-08, FR-09, FR-11, FR-13, FR-21, FR-22, FR-23, FR-25, FR-28, FR-29 ([основа](../product-requirements.md)); FR-24 ([sf-note](../sf-note/requirements.md)).

Устройство: [общее](../core/design.md), [этапа](design.md).

## Распределение работы на этапе

| Действие | Агент | Детерминированный инструмент |
|---|---|---|
| Проверка требований | Сообщает, правил ли `spec.md` в этой сессии и есть ли отдельный агент; проверяет полноту, смысл и противоречия в отдельном контексте, записывает результаты в `_work/review.md`; записывает решения по замечаниям | Выбирает путь проверки, проверяет оформление замечаний и учитывает их разбор |

## Функциональные требования

**FR-17.** Проверка требований выполняется этапом `sf-review` в отдельном контексте: отдельным агентом — рекомендуется, либо в новой сессии, запускаемой пользователем по готовой команде. Если отдельный агент недоступен, проверка проводится только в новой сессии; продолжение проверки в текущей сессии не предлагается. `sf-review` сразу записывает результаты в `_work/review.md`, а не оставляет их только в переписке. Проверяющий агент выявляет проблемы; изменение требований происходит после принятия решений по результатам. Разбор с пользователем опирается на сохранённый файл.

**FR-18.** Сначала расширение разбирает с пользователем блокирующие проблемы по одной. Затем предлагает разобрать все остальные замечания, выбранные замечания либо отклонить их.

**FR-19.** Для отдельной проблемы пользователь может принять рекомендацию, дать своё решение, отложить вопрос или отклонить замечание. Отложенный вопрос сохраняется в `questions.md`. Отклонение означает явное решение пользователя не принимать вывод проверяющего, а не молчаливое исчезновение проблемы.

Отложенная блокирующая проблема продолжает препятствовать одобрению (FR-21).

**FR-20.** После исправлений агент кратко показывает, что изменилось, выполняет автоматические проверки и предлагает **«Повторить проверку требований»** либо **«Одобрить»**, если для одобрения нет препятствий. Повторная проверка ИИ необязательна. Исключение — отложенная блокирующая проблема: после ответа на её вопрос препятствие снимает только повторная проверка (FR-19). Если ответ выявляет новые вопросы, применяется FR-11.

## Сценарии

- **Когда** отдельный агент для проверки недоступен, **тогда** пользователь получает команду `sf-review` для новой сессии, а проверка здесь не предлагается (FR-17).
- **Когда** `sf-review` выполнил проверку, **тогда** результаты записаны в `_work/review.md` и доступны для последующего разбора (FR-17).
- **Когда** проверка выявила блокирующую проблему, **тогда** она разбирается с пользователем, а простое откладывание не разрешает одобрение (FR-18, FR-19, FR-21).
- **Когда** на вопрос по отложенной блокирующей проблеме ответили, **тогда** одобрить можно после повторной проверки, раздел которой не содержит этой проблемы (FR-19, FR-20, FR-21).

Тесты: [tests/mcp/status/](../../tests/mcp/status/), [tests/mcp/check/](../../tests/mcp/check/) и [tests/mcp/link/](../../tests/mcp/link/) — путь проверки, вход `sf-review`, замечания и переходы после проверки, проверка `_work/review.md` и условия одобрения, ссылки на замечания.
