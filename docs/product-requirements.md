# Требования к расширению Spec Forge

## Назначение документа

Это единый источник продуктовых требований для разработчиков и агентов, которые разрабатывают **само расширение Spec Forge**. Это не документ пользовательской задачи и не инструкция для постоянной загрузки в контекст агента, который пользуется расширением.

Изменения поведения расширения сначала согласуются с владельцем и отражаются в этом файле через PR. Реализация должна соответствовать актуальным требованиям. Не заводить параллельное описание процесса с другими правилами. README даёт краткое описание продукта, AGENTS.md задаёт правила разработки.

Документ фиксирует согласованные решения. Границы последующего проектирования перечислены в конце. Новые развилки поведения требуют согласования с владельцем. Согласование этого документа не разрешает начинать реализацию: для неё требуется отдельное поручение владельца.

## Цель и границы

Spec Forge — расширение только для GigaCode CLI, рассчитанное на Qwen3.8-flash-next, GLM-5.3-Flash и DeepSeek-V4.1-Flash.

Текущий объём продукта — самостоятельный законченный путь от идеи до одобренного документа с функциональными требованиями (FR). Пользователь получает описание того, что должна делать система, для кого, при каких условиях и с каким результатом.

Результат должен быть полезен уже в этом объёме. Нельзя оставлять непонятным основное поведение в расчёте на будущие этапы. Объём обсуждения и документов соответствует задаче: простая задача остаётся простой.

Отдельные этапы детальных сценариев, архитектуры, разделения работы и написание кода в текущий объём не входят. Дальнейшее расширение ответственности продукта согласуется отдельно через этот документ.

## Участники и ответственность

| Участник | Ответственность |
|---|---|
| Пользователь | Описывает идею, принимает решения о поведении и границах задачи, отвечает на вопросы и одобряет требования |
| Агент | Изучает доступные факты, раскрывает требования, выявляет противоречия и неизвестное, предлагает варианты и объясняет рекомендации |
| Детерминированные инструменты | Выполняют механические действия и проверки, помогают определять доступный следующий шаг и продолжать процесс |
| Бизнес, разработчик или другой участник | Помогает ответить на вопросы, которые пользователь пока не может решить; необходимость помощи сохраняется в вопросе |

Размышление о содержании выполняет ИИ. Для механики и проверок результатов его работы приоритет имеют детерминированные инструменты. Они не подменяют оценку смысла проверкой формы.

Правила и справки должны помогать текущей работе, не дублировать механические проверки и не раздувать суммарный контекст. Пользовательские сообщения — на понятном русском языке; внутреннее устройство расширения не должно становиться обязанностью пользователя.

## Язык общения и документов

Агент, который использует расширение для подготовки требований, в вопросах, рекомендациях, объяснениях и создаваемых документах использует понятный русский язык. Он избегает англицизмов, кальки и технического жаргона, если есть понятный русский вариант. Необходимые термины кратко объясняет при первом использовании. Точные имена команд, файлов, технологий и идентификаторы сохраняет.

При реализации это требование должно стать коротким общим правилом для агента, использующего расширение, без повторения в каждом скилле. Наличие правила в корневом AGENTS.md для разработчиков не заменяет инструкцию для такого агента. Сам этот документ требований в его постоянный контекст не включается.

## Распределение работы между агентом и инструментом

Эту таблицу обновляют вместе с требованиями при изменении процесса. Она закрепляет ответственность, но не задаёт команды, внутренние состояния или форматы хранения.

| Действие | Агент | Детерминированный инструмент |
|---|---|---|
| Изучение источников | Определяет, что относится к задаче, извлекает смысл; готовит задание для отдельного окна, если оно нужно | Проверяет доступность файлов и выполняет механические операции |
| Выяснение FR | Выбирает вопросы, выявляет зависимости, предлагает решения | Сохраняет вопросы и решения, выдаёт сохранённое состояние |
| Открытые вопросы | Определяет, почему нужен ответ и мешает ли его отсутствие подготовке требований | Учитывает открытые вопросы и запрещает одобрение, пока они есть |
| Подготовка требований | Формулирует FR и примеры по принятым решениям, определяет смысловые связи | Проставляет однозначно определяемые ссылки, проверяет структуру, номера и существование целей ссылок между файлами |
| Переходы и возобновление | Учитывает команду входа и намерение пользователя, объясняет результат работы и содержательные препятствия | Восстанавливает сохранённое состояние, определяет доступные действия и предлагает следующий шаг |
| Проверка требований | `sf-review` проверяет полноту, смысл и противоречия в отдельном контексте, готовит результаты для `_work/review.md` | Выполняет формальные проверки, сохраняет результаты, учитывает разбор замечаний |
| Ответ, новая информация и исправления | Через `sf-note` определяет затронутые решения и требования, запускает соответствующее обсуждение или обновление | Сохраняет изменения, обновляет однозначно определяемые ссылки и повторяет формальные проверки |
| Одобрение | Передаёт явное решение пользователя; при изменениях определяет, затронут ли смысл требований | Проверяет условия и фиксирует одобрение; по сохранённой оценке изменения смысла требует повторного одобрения |

Инструмент проверяет, что у FR указан существующий источник решения. Соответствие смысла FR этому решению проверяет агент. Важность вопроса оценивает агент; ограничение перехода по сохранённой оценке исполняет инструмент.

Указания выше о сохранении решений и отметке вопроса решённым описывают действие расширения: агент готовит содержание и оценку, инструмент выполняет запись. Формальная проверка не доказывает правильность содержания. Пользователь остаётся тем, кто принимает решения и одобряет требования.

## Документы пользовательской задачи

Эти имена обозначают результаты работы расширения над задачей пользователя. Временные файлы находятся в папке `_work/` внутри папки задачи. Точные форматы документов и размещение самой папки задачи определяются при проектировании.

| Документ | Назначение |
|---|---|
| `brainstorming.md` | Исходный запрос, источники, обсуждённые вопросы, рекомендации, принятые решения и границы задачи |
| `spec.md` | Первичные бизнес-требования с FR, понятным ожидаемым поведением и примерами; требования основаны на решениях пользователя |
| `questions.md` | Единое место для открытых вопросов и памятка о необходимой помощи; после решения сохраняет ответы |
| `_work/context.md` | Результат изучения источников, в том числе при передаче исследования в отдельное окно |
| `_work/review.md` | Результаты проверки требований этапом `sf-review`, используемые для разбора замечаний |

Принятая последовательность: идея → `sf-grill` → `brainstorming.md` → `sf-spec` → `spec.md`. Открытые вопросы на этом пути ведутся в `questions.md`.

## Пользовательский путь и функциональные требования

### Начало и изучение источников

**FR-01.** Агент сначала выслушивает идею пользователя и проверяет доступные источники. Если сведений недостаточно, спрашивает о полезном коде, документации или требованиях. Отдельный обязательный этап сбора источников не нужен.

**FR-02.** Агент изучает относящиеся к задаче сведения и использует их при выяснении требований. Доступные факты ищет самостоятельно; решения о желаемом поведении принимает пользователь. Уже известное не должно превращаться в повторную анкету.

После изучения источников агент кратко излагает понимание задачи и сразу задаёт содержательный вопрос. Отдельного подтверждения понимания не требуется.

### Выяснение требований: sf-grill

**FR-03.** `sf-grill` максимально раскрывает FR в границах задачи: участников, действия, условия, бизнес-правила, ожидаемые результаты и существенные исключения. Вопросы вытекают из идеи и ответов пользователя; справочник тем не превращается в обязательную анкету.

Детальные уточнения вроде точных текстов сообщений и длины полей не являются обязательной целью этого этапа. При этом нельзя отложить решение, без которого не определено основное поведение.

**FR-04.** Агент задаёт небольшие связанные группы вопросов, объясняет рекомендации и ждёт ответов. Зависимый вопрос задаётся после решения его предпосылок. Ответы могут порождать новые вопросы.

**FR-05.** Агент может предлагать потенциально недостающие возможности и объяснять пользу. Предложение становится требованием только после решения пользователя. Рекомендация агента не приравнивается к принятому решению.

**FR-06.** `sf-grill` использует скилл `grilling`, текст которого включён в расширение в составе `sf-grill`. Возможность пользовательского переопределения `grilling` в текущий объём не входит.

Источник: [mattpocock/skills — grilling](https://github.com/mattpocock/skills/tree/main/skills/productivity/grilling). При включении необходимо сохранить применимые условия лицензии и сведения об авторстве рядом с текстом. В этом документе зафиксирован выбор источника, а не выполненная установка.

Применение `grilling` должно соответствовать этому процессу: небольшие группы вопросов, продолжение независимых тем и сохранение нерешённых вопросов. Требования исходного скилла о полном раунде всех доступных вопросов и закрытии всех веток не должны отменять эти правила.

**FR-07.** В `brainstorming.md` сохраняются принятые решения отдельно от рекомендаций. Документ служит основанием для подготовки требований.

### Открытые вопросы

**FR-08.** Все открытые вопросы сохраняются в `questions.md` с указанием этапа возникновения и того, чья помощь нужна. Если пользователь не может ответить без бизнеса или разработчика, вопрос остаётся открытым; агент не выдумывает ответ.

**FR-09.** Нерешённый вопрос не останавливает обсуждение независимых тем. Вопрос считается блокирующим подготовку требований, если без ответа нельзя определить основное поведение либо ответ может существенно изменить собранные требования. Агент объясняет, что именно мешает продолжению.

**FR-10.** Подготовить `spec.md` можно с неблокирующими открытыми вопросами. При наличии блокирующих вопросов сначала требуется их решение.

**FR-11.** После получения ответа агент выясняет связанные вопросы, если они возникли, обновляет решения и требования, затем отмечает вопрос решённым и сохраняет ответ в `questions.md`. Сам факт получения ответа не означает, что все зависимые неизвестные устранены.

Явное решение пользователя «не входит в задачу» закрывает вопрос. Простое откладывание вопроса не закрывает его.

### Переход к требованиям и выбор сессии

**FR-12.** Когда обсуждение завершено и нет блокирующих вопросов, агент предлагает: **«Обсуждение завершено. Подготовить документ с требованиями?»** Отдельное предварительное подтверждение «Всё верно описали?» не требуется.

**FR-13.** При смене этапа расширение предлагает новую сессию как рекомендуемый вариант и оставляет возможность продолжить в текущей. Исключение — проверка требований `sf-review`: она выполняется в отдельном контексте по FR-17. При продолжении незавершённого этапа рекомендуется текущая сессия. Для новой сессии пользователь получает готовую команду и запускает её сам.

Расширение ведёт пользователя по пути: показывает следующий доступный шаг и объясняет препятствия. Пользователю не требуется самостоятельно определять последовательность действий. Точная компоновка предложения перехода и выбора сессии не задаётся этим документом.

### Подготовка требований: sf-spec

**FR-14.** `sf-spec` переводит принятые решения в `spec.md`. Документ содержит цель, FR с понятным ожидаемым поведением и примерами, границы задачи и связь требований с принятыми решениями. Агент не добавляет несогласованные правила.

**FR-15.** Обнаруженные при подготовке требований пробелы сохраняются в `questions.md` с этапом возникновения. Если пробел блокирует определение основного поведения, агент обсуждает его с пользователем сразу. Неблокирующий пробел выносится на последующий разбор открытых вопросов; подготовка определённых требований продолжается. Самовольные ответы недопустимы. Разбор открытых вопросов должен завершиться до одобрения документа.

**FR-16.** После подготовки требований выполняются автоматические проверки. Затем пользователь выбирает **«Проверить требования»** — рекомендуется, либо **«Одобрить»**, если выполнены условия одобрения. При препятствиях расширение объясняет, что требуется решить.

Проверка ИИ необязательна. Пункт «Упростить формулировки» в текущий процесс не входит.

### Проверка ИИ и разбор результатов

**FR-17.** Проверка требований выполняется этапом `sf-review` в отдельном контексте: отдельным агентом — рекомендуется, либо в новой сессии, запускаемой пользователем по готовой команде. Если отдельный агент недоступен, проверка проводится только в новой сессии; продолжение проверки в текущей сессии не предлагается. `sf-review` сразу записывает результаты в `_work/review.md`, а не оставляет их только в переписке. Проверяющий агент выявляет проблемы; изменение требований происходит после принятия решений по результатам. Разбор с пользователем опирается на сохранённый файл.

**FR-18.** Сначала расширение разбирает с пользователем блокирующие проблемы по одной. Затем предлагает разобрать все остальные замечания, выбранные замечания либо отклонить их.

**FR-19.** Для отдельной проблемы пользователь может принять рекомендацию, дать своё решение, отложить вопрос или отклонить замечание. Отложенный вопрос сохраняется в `questions.md`. Отклонение означает явное решение пользователя не принимать вывод проверяющего, а не молчаливое исчезновение проблемы.

Отложенная блокирующая проблема продолжает препятствовать одобрению. По окончательному правилу FR-21 любой оставшийся открытый вопрос также препятствует одобрению, даже если не мешал подготовке документа.

**FR-20.** После исправлений агент кратко показывает, что изменилось, выполняет автоматические проверки и предлагает **«Повторить проверку требований»** либо **«Одобрить»**, если для одобрения нет препятствий. Повторная проверка ИИ необязательна. Если ответ выявляет новые вопросы, применяется FR-11.

### Одобрение и завершение

**FR-21.** Одобрение выполняется по решению пользователя только после решения всех открытых вопросов, разбора блокирующих проблем проверки и успешных автоматических проверок. Агент не одобряет документ самостоятельно.

Разрешение подготовить документ с неблокирующими вопросами не означает разрешения одобрить его с такими вопросами. Прежний вариант одобрения с открытыми вопросами заменён этим правилом.

**FR-22.** После одобрения агент сообщает **«Документ с требованиями одобрен»** и даёт ссылку на `spec.md`. При напоминании о вопросах достаточно ссылки на `questions.md`, без перечисления содержимого. На момент одобрения нерешённых вопросов уже нет; файл может хранить историю ответов.

На этом текущий процесс завершён. Для получения результата не требуется проходить будущие этапы расширения.

### Возобновление, новые сведения и поддержка процесса

**FR-23.** Пользователь может войти в работу через разные команды расширения. Агент учитывает команду и намерение пользователя, а вместе с детерминированным инструментом помогает определить, где пользователь остановился, и продолжить с подходящего действия по сохранённым материалам. Если задача явно указана, используется она. Если подходит одна начатая задача, работа продолжается с ней; если несколько — расширение спрашивает пользователя. Для новой задачи автоматически предлагается имя папки с возможностью его изменить.

**FR-24.** Новые сведения могут поступить обычным сообщением, например «Появилась дополнительная информация…», или через `sf-note <text>`. Скилл `sf-note` своим описанием помогает агенту распознать такую просьбу и применить единый процесс: выяснить, какие решения и требования затронуты, запустить соответствующее обсуждение и обновление документов. Это применяется и к сведениям после одобрения. Если новые сведения меняют смысл требований, прежнее одобрение больше не относится к изменённому документу: требуется повторное одобрение по FR-21. Одно лишь поступление заметки без изменения смысла требований не требует повторного одобрения. `sdd-decide` — ориентир по назначению, а не готовая реализация для копирования.

**FR-25.** Автоматические проверки контролируют формальную согласованность документов и ссылок между ними: цель ссылки существует, ссылка не ведёт в отсутствующий файл или запись. Инструмент проставляет ссылки, которые можно определить однозначно по сохранённым данным, и сообщает пользователю, где найдена ссылка в тупик. Смысловую связь определяет агент; инструмент не угадывает её по тексту.

**FR-26.** Если для сбора сведений нужен отдельный агент, но он недоступен, пользователь выбирает: собрать сведения в отдельном окне либо подтвердить продолжение исследования здесь. Для отдельного окна агент готовит задание или команду; результат исследования сохраняется в `_work/context.md`. После завершения пользователь сообщает основному агенту, что файл готов, и агент использует его для продолжения работы. Молчаливой замены отдельного исследования работой в текущем окне нет. Для проверки требований ИИ действует FR-17: при отсутствии отдельного агента используется только новая сессия.

### Недоступность источника или инструмента

**FR-27.** Если источник недоступен, агент сообщает пользователю о проблеме и ждёт его решения: двигаться дальше без этого источника или пользователь сейчас исправит доступность. Агент не выбирает пропуск источника самостоятельно. Продолжение без источника не разрешает выдумывать недостающие сведения и не отменяет правила открытых вопросов FR-08–FR-10.

**FR-28.** Если агент не видит инструмент расширения, он ищет его через поиск инструментов, пробуя разные запросы. Отсутствие инструмента в первоначальном списке не означает, что он не работает. Если вызов инструмента не удался, агент предупреждает пользователя; не сообщает о неуспешной операции как о выполненной. Дополнительный процесс восстановления этим требованием не вводится.

### Сохранение материалов

**FR-29.** Все временные материалы задачи, включая `context.md` и `review.md`, хранятся в `_work/`. После завершения сохраняются `brainstorming.md`, `questions.md` и материалы `_work/`. Автоматическая очистка в текущий объём не входит; временное назначение файла не означает его удаления после одобрения.

## Проверочные ситуации для будущей реализации

Это критерии ожидаемого поведения, а не утверждение, что реализация уже существует или проверена.

| Ситуация | Ожидаемый результат |
|---|---|
| В доступных материалах достаточно сведений | Агент изучает их без обязательного отдельного этапа сбора источников |
| Пользователь не знает ответа и ждёт бизнес | Вопрос сохранён с этапом и необходимой помощью; независимые темы обсуждаются дальше |
| Не определено основное поведение | Агент объясняет блокировку; подготовка требований не начинается |
| Остались только неблокирующие вопросы | Можно подготовить документ, но нельзя его одобрить |
| Агент предложил дополнительную возможность, пользователь не согласился | Возможность не появляется среди принятых FR |
| Пользователь завершил обсуждение | Одно предложение подготовить документ, без отдельного «Всё верно описали?»; доступен выбор сессии |
| Пользователь предпочёл текущую сессию для подготовки требований | Процесс продолжается в ней, новая сессия не навязывается |
| Пользователь отказался от проверки ИИ | Одобрение доступно при выполнении FR-21 |
| Проверка выявила блокирующую проблему | Проблема разбирается с пользователем; простое откладывание не разрешает одобрение |
| Ответ породил зависимые вопросы | Агент обсуждает их и обновляет документы, не закрывает ветку только по факту первого ответа |
| После изучения источников агент готов начать обсуждение | Кратко излагает понимание и сразу задаёт содержательный вопрос |
| При подготовке требований выявлен пробел | Блокирующий обсуждается сразу; неблокирующий сохраняется для разбора открытых вопросов до одобрения |
| Пользователь вернулся через команду расширения | Агент и инструмент учитывают команду и сохранённые материалы, помогают продолжить с места остановки |
| Пользователь сообщил новые сведения обычным текстом или через `sf-note` | Агент определяет затронутое содержание и запускает соответствующее обсуждение или обновление |
| Ссылка ведёт в отсутствующий файл или запись | Автоматическая проверка показывает, где проблема; инструмент не выдумывает смысловую замену |
| Отдельный агент для исследования недоступен | Пользователь выбирает другое окно с заданием и `_work/context.md` либо явно подтверждает продолжение здесь |
| Источник недоступен | Агент сообщает о проблеме и ждёт выбора: продолжить без источника или исправить доступность |
| Агент не видит инструмент расширения | Ищет его поиском инструментов, пробуя разные запросы |
| Вызов инструмента не удался | Предупреждает пользователя, не заявляя об успешном выполнении |
| Отдельный агент для проверки недоступен | Пользователь получает команду `sf-review` для новой сессии; проверка здесь не предлагается |
| `sf-review` выполнил проверку | Результаты записаны в `_work/review.md` и доступны для последующего разбора |
| Подходящих начатых задач несколько | Расширение просит выбрать; явно указанная задача не заменяется другой |
| Создаётся новая задача | Предлагается имя папки, которое пользователь может изменить |
| `sf-note` меняет смысл одобренных требований | Изменённый документ требует повторного одобрения по FR-21 |
| Процесс завершён | Протокол, вопросы и материалы `_work/` сохраняются, автоматическая очистка не выполняется |
| Все вопросы решены, проверки пройдены | Пользователь может одобрить документ; получает сообщение и ссылку без перечня вопросов |

## Что можно использовать из sdd-planner

[sdd-planner](https://github.com/KrtNinja/sdd-planner) — прежний проект и источник отдельных наработок, а не обязательная основа поведения или архитектуры.

Для осмысленной адаптации подходят шаблоны `skills/sdd-grill/assets/brainstorming.md`, `skills/sdd-spec/assets/spec.md`, справочник `skills/sdd-grill/references/questions.md` и приёмы сопровождения переходов. Перед переносом каждый элемент проверяется на соответствие этому документу.

Не переносить автоматически обязательный обход всех тем, прежнюю глубину детализации, дополнительные подтверждения, внутренние команды, состояния, способы хранения и последующие этапы. Наличие правила в старом проекте не является его согласованием для Spec Forge.
