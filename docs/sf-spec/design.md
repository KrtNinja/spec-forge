# sf-spec: устройство

Как выполнены [требования этапа](requirements.md). Опирается на [общее устройство](../core/design.md).

Документы, которые скилл читает после `status`: `brainstorming.md`, `questions.md`, `spec.md`, если он есть.

## Вход

Сверх общих правил входа и таблицы переходов:
- задачи с названным именем нет — `sf-spec` новую задачу не начинает и отправляет к `/spec-forge:sf-grill`;
- обсуждение не закончено, если `spec.md` нет, а источники не изучены или вопросы блокируют; иначе — подготовить `spec.md`.

## Подготовка требований

Граница FR-30 задаётся в `rules/spec-forge.md`.

Ни путей и файлов, ни классов и методов. Это правило в тексте `sf-spec`, а не проверка: проверка не отличит ссылку на код от имени файла, которое описывает поведение, например выгрузку `orders.csv`. В `brainstorming.md` и `_work/` ссылки на код допустимы.

Скилл объединяет близкие правила одной темы в одно FR по FR-14. «Технические детали» основанием для FR не служат (FR-30). Пример добавляется по FR-14, обязательной пары граничных значений нет. Пробелы вне FR-30 вопросами `Q-…` не записываются; остальные обрабатываются по FR-15.

## Вид spec.md

Под «Требованиями» заголовки третьего уровня — необязательные темы, четвёртого — записи, в том числе без темы. У темы может быть поясняющий текст. Запись — ``#### `FR-01` Поиск по полному номеру``: номер в обратных апострофах и короткое название из букв, цифр, пробелов и дефиса, слова через один пробел, без пробелов по краям. Заголовок третьего уровня с номером FR — ошибка уровня, четвёртого с неверным номером или названием — ошибка заголовка записи. Ошибочный заголовок не становится темой. Без записей раздел проверку не проходит.

После заголовка — правило обычным текстом, необязательная строка `> Пример: …`, затем обязательная строка `<sub><sup>Основание: D-01, D-02</sup></sub>`. Каждое поле — не больше одного раза. Номера оснований без обратных апострофов; `link` превращает их в ссылки. Образец — в `skills/sf-spec/SKILL.md`. Правило об акцентах по FR-14 — только в `rules/spec-forge.md`: оно нужно и при правках через `sf-review` и `sf-note`.

Разбор заголовка и полей FR сосредоточен в `server/records.mjs`; `check`, `status`, подсчёт номеров и зависимостей используют его. Записи D, Q и R сохраняют общий прежний разбор. Прежний формат FR не поддерживается.

Якорь FR вычисляется в `server/links.mjs` из всего заголовка: без решёток и обратных апострофов, в нижнем регистре, с дефисами вместо пробелов. Для приведённого заголовка это `#fr-01-поиск-по-полному-номеру`; буква «ё», цифры и дефисы сохраняются. Явный `<a id>` не нужен. Эту же функцию используют проставление, исправление и проверка ссылок. Ссылки с номером FR после переименования исправляет `link`; старый якорь — ошибка `check`. Якоря D, Q и R не меняются.

Остаётся модели: FR-14, FR-15, FR-30.
