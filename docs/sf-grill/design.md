# sf-grill: устройство

Как выполнены [требования этапа](requirements.md). Опирается на [общее устройство](../core/design.md).

Документы, которые скилл читает после `status`: `brainstorming.md`, `questions.md`, `_work/context.md`, если они есть.

## Новая задача

Новую задачу начинает только `sf-grill`.

- `/spec-forge:sf-grill` без аргументов при одной подходящей задаче продолжает её. Ответ `status` называет задачу и подсказывает, как начать другую: `/spec-forge:sf-grill` с описанием идеи. Отдельного вопроса агент не задаёт.
- Идея в команде тоже начинается со `status` без задачи. Если он предложил начатую задачу, агент читает её `brainstorming.md` и сравнивает с идеей: та же задача — продолжает её, и идея становится новыми сведениями для обсуждения; другая — начинает новую задачу.
- Имя папки — по FR-23. Своё правило команды может выглядеть как `JIRA-555`. Агент предлагает имя латиницей строчными буквами через дефис, например `order-search`.
- `status` допускает латинские буквы, цифры, дефис, `_` и `.`, первый знак — буква или цифра, и проверяет, что папки с таким именем нет. Папку и `brainstorming.md` создаёт агент.
- Агент создаёт `brainstorming.md` сразу после выбора имени папки — до изучения источников и вопросов о требованиях. Загрузка правил до первого вопроса описана в [общем устройстве](../core/design.md#контекст).

## Обсуждение

- Вопросы задаются блоками до 4 по общему правилу выбора. Вариантов 2–4. Пояснение длиннее двух фраз даётся коротким сообщением перед блоком.
- Вместо справочника тем одна строка с шестью сторонами FR из FR-03: участники, действия, условия, бизнес-правила, результаты, существенные исключения. По ней агент проверяет, что раскрыто. Анкетой она не служит.
- Вопрос без ответа записывается в `questions.md` (FR-08) и считается пройденной веткой раунда.
- Вопросов, которые можно задать сейчас, не осталось — агент вызывает `status` и предлагает переход, только если `status` его показал. Пока есть неизученные или недоступные источники, `status` выдаёт их, а не переход: вопросы, ждущие изучения, ещё не заданы. Есть блокирующие вопросы — `status` их перечисляет, агент объясняет, что мешает (FR-09). Нет — `status` показывает переход: новая сессия (рекомендуется) — `/clear` или перезапуск окна, затем `/spec-forge:sf-spec <имя>`, или эта сессия, и последней строкой Tip. Агент задаёт вопрос FR-12 с вариантами: в новой сессии, в этой сессии, продолжить обсуждение (FR-13). В этой сессии он сам запускает скилл `sf-spec`.
- Факты для ответа собирает отдельный агент по заданию из `status`: нужен факт посреди обсуждения — агент добавляет источник в «Источники» и вызывает `status`. Вопросы, не зависящие от поиска, задаются сразу, не дожидаясь результата.
- Остаётся модели: FR-01, FR-02, FR-05.

## grilling

Текст `grilling` записан прямо в `skills/sf-grill/SKILL.md` на языке оригинала, без перевода. Он стоит одним куском между служебными строками:

```
<!-- grilling: начало (MIT, см. LICENSE-grilling) -->
…
<!-- grilling: конец -->
```

Все правила процесса — в `sf-grill` вне этих строк. Чтобы убрать `grilling`, удаляется кусок между ними вместе с самими строками, и правила процесса при этом не теряются.

Логика раундов исходного скилла сохраняется: раунд — все вопросы, которые можно задать сейчас; обсуждение заканчивается, когда таких вопросов не осталось. Внутри текста правятся только фразы, противоречащие процессу. Каждая такая фраза заменяется короткой отсылкой к правилам `sf-grill`, например «show the round per the rules above», а сами правила внутрь не переносятся. Правятся фразы:
1. о показе всего раунда одним сообщением — отсылка к блокам до 4 вопросов;
2. о метках вопросов раунда `Q1`, `Q2` — убираются, чтобы не путать их с записями `Q-…`;
3. об ответе «да» в знак согласия с рекомендацией — отсылка к выбору из 2–4 вариантов;
4. о завершении с подтверждением общего понимания — отсылка к правилу завершения;
5. об отправке отдельного агента за фактами — отсылка к заданию из `status`.

`skills/sf-grill/LICENSE-grilling` содержит текст лицензии MIT и уведомление об авторстве, источник с коммитом и список правок. В контекст модели этот файл не загружается.

## Изучение источников

- Изучение источников всегда выполняет отдельный агент, независимо от объёма. Источников нет — изучения нет. Отдельного агента нет — действует FR-26.
- Источники агент записывает в раздел «Источники» `brainstorming.md`: пункт начинается с пути в обратных апострофах или со ссылки. `status` читает их оттуда. Пункт другого вида источником не считается.
- Агент изучения записывает каждый источник в `_work/context.md`: открылся — в подраздел «Изучено», не открылся — в «Не изучено» с причиной. Источник изучен, если его путь или адрес встречается в «Изучено».
- Задание выдаётся только на неизученные источники. Недоступен неизученный источник, путь которого не найден или который записан в «Не изучено»; ссылки на наличие не проверяются. Пока есть недоступные, `status` выдаёт только их список, без задания, и дальше действует FR-27:
  - продолжить без источника — агент записывает решение `D-…` и убирает источник из «Источников» `brainstorming.md`;
  - доступ восстановлен — агент убирает источник из «Не изучено», и `status` снова выдаёт на него задание.
- Задание выдаёт `status` по заготовке: прочитать `brainstorming.md`, список источников, куда и в каком виде записать результат, в конце вызвать `check`. Агент добавляет только то, что нужно выяснить. Одно и то же задание подходит и для отдельного агента, и для другого окна.
- Нужен новый факт из уже изученного источника — агент убирает его пункт из «Изучено», и `status` снова выдаёт на него задание. Упоминание источника в «Фактах» изучением не считается.
- Повторное изучение дописывает факты в разделы `_work/context.md`, а не перезаписывает файл.
- `check` проверяет заголовки `_work/context.md`, если файл есть. Отсутствие файла — не ошибка: пока источник не записан в «Изучено», `status` выдаёт на него задание. Смысл фактов `check` не оценивает.
