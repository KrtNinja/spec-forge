## Что проверяют критерии

| Замечание | Критерии | Фактический результат до реализации |
|---|---|---|
| Утраченное одобрение при входе без имени | Для обеих команд: `status/spec-changed-*` и `status/review-changed-*`, случаи `one-task`, `several-tasks`, `open-question`, `blocking-remarks` | 8 падений: изменённая задача исключается из поиска; список выбора теряет её |
| Явно указанная задача и завершённые задачи | Новый `status/review-changed-named-task`; прежние `approved-changed`, `spec-*tasks`, `review-*tasks` | Проходят. В трёх прежних случаях `spec-no-tasks`, `spec-one-task`, `spec-several-tasks` неполные данные с выдуманной суммой заменены полноценным одобренным документом; ожидаемые ответы сохранены |
| Ошибка записи `link` | Два теста в `tests/protocol.test.mjs`: запрет записи `brainstorming.md` и `spec.md`, ответ ошибки, `ping`, состояние файлов, повтор и ещё один вызов без изменений в одном процессе | 2 падения: сервер выдаёт необработанный `EACCES` и не отвечает. Чтение доступно, запрет записи подтверждён реальным открытием файла для записи |
| Переход с неблокирующим вопросом | Уточнены `readyForSpec` и 5 связанных ожидаемых ответов; существующие случаи блокирующих вопросов и запрета одобрения сохранены | Проходят |
| Начало работы | README: окружение, получение и подключение, запуск в проекте, первая идея, четыре команды, документы и завершение | Текст подготовлен; выполнение новым пользователем ещё не проверено |

Дополнительно на неизменённой логике проверены шесть вызовов с явным `task`: обе команды для изменённого документа, открытого вопроса и блокирующего замечания. Ответы точно совпали с новыми ожиданиями. Это подтверждает сохранение приоритетов таблицы переходов; новые правила обработки вопросов не введены.

Тесты записи используют существующие документы `link/numbers` и проверяют содержимое байт в байт, включая CRLF. При запрете записи `spec.md` до сбоя успевают записаться **brainstorming.md и questions.md**. Ожидание повторного вызова — 5 добавленных ссылок; при сбое на первом файле — 13. Ещё один вызов должен дать 0 правок. Проверки повтора пока не достигаются из-за падения сервера; их успешность не заявляется.

## Тексты для проверки владельцем

Подсказка перехода:

> Дальше: продолжить обсуждение. Когда обсуждение завершено — предложить подготовить требования. Неблокирующие вопросы могут оставаться открытыми.

Ошибка записи после двух документов:

```text
Не удалось записать `docs/order-search/spec.md`. Работа со ссылками остановлена.

До ошибки записаны: `docs/order-search/brainstorming.md`, `docs/order-search/questions.md`.

Проверьте указанный файл и возможность записи, затем повторите `link`.
```

Если до ошибки ни один файл не был успешно записан, второй абзац: «До ошибки ни один файл не записан.» Полная атомарность и откат нескольких документов не требуются.

## Что осталось проверить в GigaCode CLI

CLI в окружении отсутствует (`command -v gigacode` не нашёл команду). Версия CLI не установлена; ни одна из трёх целевых моделей здесь не запускалась. Поддержка версий и платформ не подтверждена.

Сверка 12 ноября 2026 с официальной документацией: [установка и `gigacode --version`](https://gitverse.ru/docs/ai/ai-assistant-gigacode/getting-started-with-gigacode/quick-start), [команды `/extensions`, `/skills`, `/mcp`](https://gitverse.ru/docs/ai/ai-assistant-gigacode/gigacode-cli/commands), [вызов скиллов и загрузка из расширения](https://gitverse.ru/docs/ai/ai-assistant-gigacode/gigacode-cli/skills). Синтаксис `gigacode extensions link` в доступных официальных страницах не подтверждён: в README он перенесён из согласованного `docs/core/design.md`. Проверка этой команды остаётся открытой, её успешный запуск не заявляется.

После реализации владельцу или агенту с доступом к GigaCode:

1. Взять проверяемую ветку, записать `git rev-parse HEAD`, `node --version`, `gigacode --version` и платформу. Сверить `gigacode extensions link --help`, выполнить начало работы из README в отдельном проекте. Если команда отличается, уточнить инструкцию до передачи коллегам.
2. Подтвердить расширение, четыре скилла и `spec_forge`; проверить загрузку общих правил при создании первого документа. Пройти путь по README без дополнительных пояснений владельца.
3. На Qwen3.8-flash-next, GLM-5.3-Flash и DeepSeek-V4.1-Flash выполнить сценарии из раздела «Проверка в GigaCode CLI после исправлений» [задания](release-readiness.md): небольшая задача до одобрения, вопросы, перерыв, отдельная проверка требований и изменение после одобрения.
4. Для каждой модели записать сюда версию CLI, Node.js, SHA, выполненные сценарии, результат и проблемы. Отдельно повторить ревью четырёх пунктов по `tools/review-spec-forge/SKILL.md` после реализации.
